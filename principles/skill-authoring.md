# Skill 编写原则

Skill 的格式、`SKILL.md` frontmatter 和目录约定遵循 Agent Skills 开放规范：

https://github.com/agentskills/agentskills

本文件只补充个人内容质量和维护规则。

## 一个 Skill 解决一个工作流

- Skill 只有在存在可重复的输入、判断、执行和验收流程时才值得创建。
- 长期开发偏好进入 `principles/`；真实项目事实留在项目自己的文档。
- Skill 名使用 `aki-<short-name>` 格式，目录名与 frontmatter `name` 一致。

## 指导优先

- 优先描述目标、边界、判断标准、执行流程、修改规则和验收条件。
- 能用一般规则表达的内容，不通过大量案例间接表达。
- 例子只在规则仍有歧义时保留，并保持最少。
- Skill 必须能在新的会话和新的项目中独立成立。

## 只保留会改变行为的信息

- 每一段内容都应改变 Agent 的判断、执行或验收方式；没有行为差异的信息删除。
- 同一事实只保留一个权威来源；已有 principle 或项目文档能够承担时直接引用。
- 当前规则表达最终有效状态，不保存纠错过程和无行为价值的演进叙述。
- 负面约束只有在能够阻止真实、容易复发且无法通过正向规则充分表达的问题时才保留。

## 修改型 Skill 必须幂等

凡是会创建或修改文件的 Skill：

- 修改前完整读取目标和相关权威文档；
- 明确自己拥有的内容范围，其他内容默认保留；
- 已存在等价内容时更新或复用，不重复追加；
- 当前事实变化时直接收敛到最新状态；
- 无法确认合并边界时显式报告，不强制整文件覆盖；
- 输入和项目事实不变时连续执行两次，第二次必须产生零语义差异；能比较 Git diff 时以零 diff 为验收标准。

受控自动维护内容可以使用稳定 managed region；只有拥有该 region 的 Skill 可以重写其中内容。

## 平台元数据

通用内容放在 `SKILL.md` 及 Agent Skills 规范支持的 `scripts/`、`references/`、`assets/` 中。平台专属 metadata 只在存在真实平台功能需求时加入。

## 验收

修改后确认：

- 触发范围和职责边界清楚；
- 引用指向当前存在的 canonical 文件；
- 内容不依赖固定会话或历史迁移叙述；
- 没有无价值案例和重复规则；
- 修改型 Skill 的所有权、合并策略和幂等性明确；
- 当前文件只保留仍会影响未来行为的内容。

版本演进由 Git 提交历史承担。
