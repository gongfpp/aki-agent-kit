# Skill 编写原则

本原则约束 `aki-agent-kit` 中所有 Skill。Skill 的职责是提供可复用的判断和执行方法，而不是保存某次会话的做法、错误或案例集合。

## 指导优先

- 优先描述目标、适用边界、判断标准、执行流程、修改规则和验收条件。
- 能用一般规则表达的内容，不通过大量例子间接表达。
- 例子只有在规则本身仍存在歧义时才保留，并保持最少；例子不能成为隐含的唯一正确实现。
- 不把某次会话中的纠错、失败方案、临时决定或 Agent 犯过的错误固化成长期规则。
- 不写依赖某个固定会话的表述；Skill 必须可以在新的会话和新的项目中独立成立。

## 只保留会改变行为的信息

- 每一段内容都应能改变 Agent 的判断、执行或验收方式；不能产生行为差异的说明应删除。
- 同一事实只保留一个权威来源。已有 `AGENTS.md`、`principles/` 或项目文档能够承担约束时，Skill 引用它，不复制一份长期漂移的副本。
- 优先表达最终应达到的状态，而不是保存达到这个状态之前的讨论过程。
- 负面约束只有在它能阻止真实且容易复发的错误、又无法通过正向规则充分表达时才保留。

## 职责边界

- 长期、普遍适用的 Agent 行为进入 `agents/`。
- 单一主题、可被多个工作流复用的规则进入 `principles/`。
- 需要主动执行、具有输入—判断—修改—验收流程的能力才做成 Skill。
- 真实项目的构建命令、架构事实、业务契约和环境限制留在项目自己的文档，不写进中央通用 Skill。

## 修改型 Skill 必须幂等

凡是会创建或修改文件的 Skill：

- 修改前必须完整读取已有目标文件和相关权威文档。
- 明确 Skill 拥有哪一部分内容，其他已有内容默认保留。
- 已存在等价内容时更新或复用，不重复追加。
- 已失效的旧内容应被替换或删除，不通过继续追加新段落来覆盖旧段落。
- 不在无法确认边界时直接整文件覆盖；发生无法安全合并的冲突时应显式报告。
- 在输入、项目事实和中央规则均未变化时，连续执行两次，第二次必须产生零语义差异；能比较 Git diff 时应以零 diff 为验收标准。

对于受控模板，可使用稳定的 managed region。Skill 只修改自己拥有的 region，region 外内容保持不变。发现重复、缺失配对或嵌套错误的标记时，不自行猜测修复范围。

## 演进记录

- 当前文档只表达当前有效状态，不为了保留历史而堆叠废弃规则。
- 完整低层历史由 Git 提交保留；影响使用方式、职责边界、兼容性或工作流的语义变化同步记录到仓库 `CHANGELOG.md`。
- Skill 或路径改名时同步更新仓库内引用；没有真实兼容消费者时，不保留无意义的旧文件副本。

## 验收

修改 Skill 后至少确认：

- 触发范围和不适用范围清楚；
- 内容以规则和判断方法为主，没有依赖固定会话的叙述；
- 引用路径和远程 URL 有效；
- 修改型 Skill 的所有权和合并策略明确；
- 重复执行不会重复插入、改写或重新排序稳定内容；
- 仓库中不存在仍指向已重命名 Skill、文件或仓库地址的过期引用。
