# Skill 编写原则

本仓库的 Skill 格式、`SKILL.md` frontmatter 和目录约定以 Agent Skills 开放规范为上游来源：

https://github.com/agentskills/agentskills

本文件只补充个人内容质量和维护规则，不重新定义一套 Skill 标准。

## 一个 Skill 解决一个工作流

- Skill 只有在存在可重复的输入、判断、执行和验收流程时才值得创建。
- 长期开发偏好进入 `principles/`；真实项目事实留在项目自己的文档；不要把所有偏好堆进 Skill。
- 名称保持短而可辨认，目录名与 frontmatter `name` 一致；在本仓库中使用 `aki-` 前缀避免全局安装时碰撞，不再追加多余的 `-skill` 后缀。

## 指导优先

- 优先描述目标、边界、判断标准、执行流程、修改规则和验收条件。
- 能用一般规则表达的内容，不通过大量案例间接表达。
- 例子只在规则本身仍有歧义时保留，并保持最少。
- 不把某次会话中的纠错、失败方案、临时决定或 Agent 犯过的错误固化成长期规则。
- Skill 必须能在新的会话和新的项目中独立成立，不依赖“当前对话专用”等隐式上下文。

## 只保留会改变行为的信息

- 每一段内容都应改变 Agent 的判断、执行或验收方式；没有行为差异的信息删除。
- 同一事实只保留一个权威来源；可以引用已有 principle 或项目文档时，不复制长期漂移的副本。
- 优先表达最终有效状态，不保存达到该状态之前的讨论过程。
- 负面约束只有在能阻止真实且容易复发的问题、又无法通过正向规则充分表达时才保留。

## 修改型 Skill 必须幂等

凡是会创建或修改文件的 Skill：

- 修改前完整读取已有目标和相关权威文档；
- 明确自己拥有的内容范围，其他内容默认保留；
- 已存在等价内容时更新或复用，不重复追加；
- 已失效内容直接替换或删除，不靠继续追加新段落覆盖旧状态；
- 无法确认合并边界时显式报告，不强制整文件覆盖；
- 输入和项目事实不变时连续执行两次，第二次必须产生零语义差异；能比较 Git diff 时以零 diff 为验收标准。

受控自动维护内容可以使用稳定 managed region；只有拥有该 region 的 Skill 可以重写其中内容。

## 平台元数据保持可选

Agent Skills 的通用内容放在 `SKILL.md` 及规范支持的 `scripts/`、`references/`、`assets/` 中。平台专属 UI metadata 只有在确实依赖对应平台功能时才加入，不为“可能有用”默认维护多份配置。

## 演进与验收

- 当前文件表达当前有效状态；完整历史交给 Git。
- 影响使用方式、职责边界、兼容性或工作流的语义变化记录到 `CHANGELOG.md`。
- Skill 或路径改名时更新所有仓库内引用，没有真实兼容消费者时删除旧路径。
- 修改后确认触发范围清楚、引用有效、没有固定会话残留、没有无价值案例堆积，并能解释重复执行为什么不会产生新差异。
