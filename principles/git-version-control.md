# Git 版本管理原则

- `main` 保持稳定，功能开发和较大修改优先在独立分支中进行。
- 一个独立需求或任务对应一个分支；同一需求的多轮迭代继续使用该分支，不按单次对话拆分。
- 每个逻辑完整、可独立理解的改动形成一个 commit，避免把无关修改混在一起。
- 在形成稳定阶段时及时 commit / push，不要求固定频率。
- 任务完成后检查改动与基本可用性，再合并到 `main`。
- 合并完成后删除已完成的任务分支。
- 未经明确确认，不执行可能破坏历史或丢失代码的 Git 操作，如 `reset --hard`、`push --force`。
- Git 操作应以保持历史清晰、方便回滚和避免代码丢失为原则；具体拆分方式由 Agent 根据实际任务判断。
