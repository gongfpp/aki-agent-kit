# aki-github-readme-skill

## 目标

把 README 作为仓库的第一入口，让陌生读者快速判断项目是什么、解决什么问题、如何开始使用、有哪些重要限制，以及下一步应查看哪里。

README 必须建立在仓库真实内容上。视觉设计、结构和措辞都服务于理解与使用，不用装饰、营销语言或未经验证的指标替代项目事实。

## 内容判断

- 先确定项目定位、目标读者和最小成功路径，再决定章节结构。
- 首屏只保留帮助读者快速判断项目价值和状态的信息；其余内容按阅读任务向后展开。
- 安装、运行、配置、构建和示例命令必须来自真实仓库或已经确认的外部契约，不能根据技术栈猜测。
- README 只承载用户和贡献者最常需要的信息；复杂设计、内部决策和容易过期的背景资料应留在更合适的专项文档。
- 标题、链接文字、代码块、图片 alt 和说明应能独立表达含义，不让理解依赖颜色、装饰或图片中的文字。
- 徽章、统计、动态组件和视觉素材只有在能帮助判断项目状态、能力或使用方式时才保留。

## 结构原则

README 的结构由真实项目决定，不强制套固定模板。组织内容时优先保证：

- 项目定位在最前面能够被快速理解；
- 最小可运行路径完整、连续且可复制；
- 核心能力和限制在读者需要做判断的位置出现；
- 深入资料有明确去向，不在 README 内重复维护；
- 已经不存在或无法验证的章节及时删除，不通过追加新说明掩盖旧内容。

## 图片与社交预览

README 内容图片用于解释实际界面、流程、架构或结果，优先使用真实项目素材，并提供准确 alt 文本。

GitHub Social Preview 是独立的分享识别素材，应按平台横向画布设计，保持单一主点、缩略图可读、足够留白和不透明背景。它不承担完整功能介绍，也不直接复用为其他平台设计的纵向封面。

生成视觉素材时，不添加仓库中不存在的功能、数据、界面或结果。无法可靠生成文字时，优先保留可后期排版的清晰空间，而不是接受不可控文字错误。

## 工作流

1. 读取仓库结构、现有 README、构建入口、运行方式、配置、许可证、截图和与使用方式直接相关的文档。
2. 区分已确认事实、缺失信息和仍需验证的推测；只把已确认事实写进最终 README。
3. 确定读者最小成功路径，并围绕这个路径组织信息层级。
4. 优先复用已有准确内容和真实视觉素材；只有现有结构阻碍理解时才重组。
5. 检查命令、路径、链接、标题层级、图片引用、alt 文本、亮暗背景可读性和移动端扫读效果。
6. 再次从陌生读者视角审计，删除重复、没有判断价值、已经可以从相邻内容直接得到的信息。

## 修改规则

- 修改前完整读取现有 README，不因为调用 Skill 就默认重写整个文件。
- 保留仍准确且位置合理的内容，只修改有事实变化、结构问题或明显表达成本的部分。
- 不顺手修改业务代码、版本、仓库设置或其他不属于 README 任务的内容。
- 在仓库事实和用户目标不变时重复执行，不应反复改写同义措辞或重新排列稳定章节；第二次执行应产生零语义差异。

## 验收

最终 README 至少满足：事实可追溯、最小使用路径可执行、章节没有明显重复、图片和链接有效、重要限制没有被视觉包装掩盖，并且没有为了“看起来完整”填入未经证实的信息。

如果关键事实仍缺失，明确指出缺口，不使用占位推测冒充完成状态。
