# aki-grill-with-context

## 目标

在开始实现之前，把计划、设计或重要决策中仍然隐含的选择暴露出来并逐层澄清。

本 Skill 自包含 grill 工作流，不依赖 `grill-me`、`grilling` 或任何外部 Skill。其访谈机制参考了 Matt Pocock 的 grilling 思路，但已针对 aki-agent-kit 的事实核验、项目边界和上下文持久化规则重新实现。

## 基本模型

把当前主题看成一棵**决策树**：

- 上层决定约束下层决定；
- 已经具备全部前置答案、现在就能回答的节点组成当前 **frontier**；
- 一轮只询问当前 frontier，不提前询问依赖尚未确定的问题；
- 用户回答后重新计算 frontier，而不是提前写死后续问题。

不要为了问题数量而继续追问。目标是消除会影响实现、验收或长期维护的隐含决策。

## 事实与决策

严格区分：

- **事实**：代码、配置、文档、运行结果、外部约束等可以调查得到的信息。由 Agent 自己读取文件、搜索、运行工具或检查环境，不把可查事实丢给用户。
- **决策**：存在真实取舍、需要偏好或产品判断的问题。必须交给用户决定，不替用户静默选择。

如果某个问题必须先取得事实证据，先调查事实；只阻塞依赖该事实的分支，其余已经可回答的 frontier 继续推进。

## 每轮提问

每轮一次给出当前全部可独立回答的问题。问题之间不能互相依赖。

每题必须包含：

1. 编号；
2. 简短标题；
3. 问题本体与必要上下文；
4. 可选项（确实存在明确选项时）；
5. Agent 的推荐答案及简短理由。

推荐只用于帮助用户判断，不视为用户已经同意。

推荐格式：

```text
Q1｜<标题>
<问题与必要上下文>

建议：<推荐选择> — <一句关键理由>

---

Q2｜<标题>
...
```

用户可以按编号回答。收到答案后：

- 更新已经确定的节点；
- 识别被答案新解锁的问题；
- 如果答案改变了上游假设，重新打开受影响分支；
- 只询问新的 frontier。

## 追问边界

优先追问真正影响结果的内容，例如：

- 目标与成功条件；
- 用户范围和主要路径；
- 范围内 / 范围外；
- 状态与数据所有权；
- 错误、失败和恢复路径；
- 兼容性与迁移边界；
- 安全、隐私和权限；
- 性能、成本、可维护性；
- 发布、验收和回滚条件；
- 游戏项目中的核心循环、失败状态、资源闭环、玩家反馈和内容生产约束。

不要机械覆盖清单。某个维度与当前问题无关时跳过。

## 无法靠讨论解决的问题

有些问题必须通过原型、运行结果、视觉对比或真实数据才能回答。遇到这类问题时：

- 不用更多措辞逼用户猜；
- 明确标记为“需要实验/原型/数据”；
- 给出最小验证方式；
- 该分支暂时挂起，其余 frontier 继续推进。

如果未解决项会阻断整个方案，则在最后把它列为明确的前置实验，而不是伪装成已经决定。

## 范围控制

如果决策树持续膨胀，先判断是否因为任务范围过大。

优先拆成几个可以独立决策和验收的子问题，再逐个 grill；不要靠设置固定问题数量强行截断复杂任务。

用户随时可以缩小范围、暂停某个分支或要求结束。用户明确表示当前信息已经足够时，不继续为了“完整”制造低价值问题。

## 共同理解确认

frontier 为空不等于可以立即实施。

先输出一份简洁的 共同理解，至少包括：

- 已确认目标；
- 关键决策；
- 明确的非目标或边界；
- 仍未解决且需要实验/外部事实的事项；
- 对实现最重要的验收条件。

然后询问用户是否确认这就是当前共同理解。

**在用户明确确认之前，不开始实现，不把讨论中的候选选择写成项目当前事实。**

如果用户要求直接实施而不继续 grill，则以用户的新指令为准，但应明确哪些关键决策仍未确认。

## 持久化

用户确认 共同理解 后：

1. 提取已经确认、长期有效、未来难以从代码重新推导的结论；
2. 调用 `aki-context-sync` 的持久化规则进行核验、去重和归属；
3. 合并到项目已有权威事实源；
4. 没有达到持久化门槛的内容不写入。

不要自动创建第二套 `CONTEXT.md`、会议纪要、聊天摘要或 ADR 体系。项目已有事实源优先。

## 验收

一次有效的 grill 应满足：

- 后续轮次明显依赖用户前一轮答案，而不是预制问卷；
- 同一轮的问题彼此没有未解决的依赖；
- 可调查事实由 Agent 自己查证；
- 用户真正拥有取舍型决策；
- 每个问题都有推荐，但推荐没有被当成默认授权；
- 遇到不能靠讨论解决的问题时转为实验/原型，而不是无休止追问；
- 未经 共同理解 确认不开始实现；
- 确认后只有值得长期保存的结论才进入项目事实源。
