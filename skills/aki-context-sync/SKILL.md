# aki-context-sync

## 目标

把只存在于当前开发会话里的有效上下文沉淀成项目当前状态的一部分，避免重要决策、隐含约束和非显然事实随着会话结束而丢失。

本 Skill 不是会话摘要、开发日志或聊天记录归档。它只持久化未来工作仍需要知道、且当前项目文档尚未准确表达的信息。

## 信息来源

综合检查：

- 当前会话中已经确认的需求、决策、约束和最终结论；
- 当前任务产生的代码、配置、测试和 Git diff；
- 项目已有 `AGENTS.md`、README、设计文档、架构文档、接口契约或其他事实源；
- 与候选事实直接相关的真实实现和调用路径。

会话只提供候选信息。能够从项目本身验证的内容以项目事实为准，不把推测直接升级为长期事实。

## 持久化门槛

候选上下文只有同时满足以下条件才写入：

- **长期有效**：当前会话结束后仍可能影响未来开发；
- **不易重建**：未来 Agent 不能通过简单读取代码、配置或已有文档廉价恢复；
- **影响决策**：知道与不知道它，会导致未来实现、审查或维护方式不同；
- **当前有效**：表达已经确认的当前状态，而不是讨论过程或临时方案。

不能通过门槛的候选直接丢弃，不为了“完整记录”落盘。

有一个明确例外：如果用户明确要求保存某个“以后可能做”的想法，或项目已经存在专门承载候选想法的事实源，可以把该想法作为**候选设计**持久化，但必须与当前需求、已确认设计和已决定计划分开，不得把它升级成当前事实。

## 内容审计

持久化当前事实，不持久化纠错和演进过程。

- 最终目标或当前实现已经完整表达正确状态时，不额外保存针对旧状态的否定说明。
- 依赖旧状态对比、迁移过程或相对时间才能成立的候选，默认视为历史信息；先改写成当前正向事实。改写后没有新增行为价值时直接丢弃。
- 只有目标文档本身明确用于历史、迁移或决策记录时，才保留演进过程。
- 能直接从代码、类型、配置、测试或目录结构稳定推导的信息通常不重复写入。
- 已有权威文档已经准确表达的内容不复制到第二处。
- 过时描述直接更新或删除，不在后面继续追加说明。
- 推测性的未来可能性、没有形成约束的讨论和一次性执行细节默认不持久化；只有用户明确要求保留或项目已有候选池明确承载此类内容时，才作为候选设计保存。

对每一句准备写入的内容执行删除测试：如果删掉它不会提高未来 Agent 做错事、误判架构或破坏契约的概率，就不要写入；对明确要求保留的灵感，则判断它是否会因为会话结束而丢失且未来仍可能被重新评估。

## 选择权威文档

先寻找现有事实源：

- Agent 工作方式和项目级长期执行约束进入项目 `AGENTS.md`；
- 简短、会直接影响文件放置位置的目录规则可以进入项目 `AGENTS.md`；
- 详细目录职责、模块边界和结构说明进入已有架构文档；没有合适事实源且确有长期价值时可使用 `docs/project-structure.md`；
- 产品、玩法和交互决策进入项目已有产品或设计事实源；
- 接口、数据或部署契约进入对应专项文档；
- README 只保留面向仓库使用者真正需要的信息。

游戏项目不在本 Skill 里重新定义 GDD、Roadmap、候选池、技术设计、美术规范或决策记录的具体文件名和职责。先按 `principles/game-development.md` 的“游戏文档职责”判断信息处于哪种语义状态，再映射到项目已经存在的权威文档或工具；项目自己的命名和流程优先。

不要把候选想法同步成当前设计、已决定计划或当前任务，除非用户已经明确做出升级决定。候选、计划、当前事实和当前实现必须保持不同状态。

不要把可从当前目录树直接读出的文件列表重新写成结构文档。只记录非显然的归属、放置、生成/手写边界和未来容易误放的规则。

只有没有合适事实源、而候选内容确实需要长期保存时，才创建 `docs/project-context.md`；该文件只承载无法合理归属到其他文档的长期上下文，没有内容的章节不创建。

## 合并规则

- 修改前完整读取目标文档，识别语义等价、冲突和已经失效的内容。
- 已有等价事实时不追加；需要更准确时直接更新原位置。
- 同一事实存在多个副本时优先保留最权威位置，并删除能够安全确认的冗余副本。
- 新内容融入现有文档结构，不制造永久的来源标记专区。
- 不重写与本次同步无关的措辞、格式或章节顺序。
- 无法判断哪个事实仍有效时，不自行选择，保留原文并报告冲突。

## AGENTS.md 边界

`AGENTS.md` 只保存会影响 Agent 工作方式的长期约束，不作为项目百科或会话记忆库。

如果项目使用 `aki-project-bootstrap`，不得修改 `<!-- aki-agent-kit:bootstrap:start -->` 与 `<!-- aki-agent-kit:bootstrap:end -->` 之间的内容；该 region 只由 bootstrap Skill 管理。

## 幂等与收敛

执行顺序：提取候选 → 与项目事实核验 → 丢弃无长期价值、可廉价重建、重复、过时和过程性信息 → 合并剩余事实 → 再次审计修改后的文档。

相同会话结论和项目状态下再次执行，结果必须保持不变。能使用 Git 时，第二次执行以零 diff 为硬性验收。不要通过时间戳、同步日志、运行次数或自动摘要制造每次都变化的文件。

版本演进由 Git 或项目明确维护的历史类文档承担；当前事实文档只表达当前有效状态。

## 输出

完成后简要说明修改了哪些权威文档、哪些类别的事实被新增/更新/删除、是否存在无法确认的冲突，以及幂等检查是否通过。
