# aki-project-init-skill

## 目标

为不同开发项目生成一个**小而稳定的本地 `AGENTS.md` bootstrap**，把会持续迭代的通用规则放在中央 GitHub 仓库 `main` 分支维护。

项目不复制整套中央规则；每次新会话开始时，由本地 bootstrap 要求 Agent 读取中央规则清单，再按项目类型获取最新规则。这样中央原则更新后，不需要逐个修改所有项目。

## 中央入口

唯一稳定入口是：

https://github.com/gongfpp/aki-skills/raw/refs/heads/main/agent-rules.yaml

该清单负责声明当前中央规则的 URL、加载条件和继承关系。以后规则文件改路径时，优先只更新清单，不让所有项目 bootstrap 跟着变化。

## 初始化流程

1. 读取当前仓库结构、现有 `AGENTS.md`、README、构建文件、测试入口和关键项目文档。
2. 判断项目类型：
   - 存在 `project.godot`、Unity `ProjectSettings/`、`.uproject` 或明确游戏运行结构时，使用 `game` profile；
   - 其他软件、App、服务、前端、后端、CLI、工具项目使用 `project` profile；
   - 不要仅凭仓库名判断。
3. 如果已经有 `AGENTS.md`，先提取其中真正项目特有的信息：构建命令、目录职责、架构事实、运行限制、发布方式和已确认约束。不要覆盖这些事实。
4. 读取 `agent-rules.yaml`，验证清单和当前 profile 需要的规则 URL 均可访问。
5. 基于 `templates/AGENTS.bootstrap.md` 生成或更新项目根目录 `AGENTS.md`。
6. `project` profile 每个新会话加载清单中的 `project`；需要产生 Git 改动时加载 `git`。
7. `game` profile 每个新会话加载 `project` + `game`；需要产生 Git 改动时加载 `git`。
8. 精简审计规则只在用户明确要求审计、精简、清理、架构收敛或删除无用复杂度时加载，不要默认塞进所有上下文。
9. 保留本地项目事实，删除与中央规则逐字重复的通用长段落，避免两套规则长期漂移。
10. 完成后检查 `AGENTS.md` 是否简洁、项目命令是否来自真实仓库、中央规则是否可访问，并按项目 Git 规范提交。

## 本地 bootstrap 的职责

本地 `AGENTS.md` 只负责四件事：

- 指示每个新会话先读取 GitHub `main` 上的中央规则清单；
- 声明项目 profile（`project` 或 `game`）；
- 保存不能放进中央仓库的项目特有事实；
- 定义项目特有规则与中央通用规则发生冲突时的优先级。

不要把中央完整规则复制进每个项目。

## 指令优先级

生成的 bootstrap 应明确：

1. 平台 system / developer 等高优先级约束；
2. 用户当前明确指令；
3. 当前项目的本地事实、契约和项目特有规则；
4. 中央 GitHub 通用规则；
5. Agent 默认行为。

中央规则是通用基线，不能覆盖项目已经确认的真实契约。

## 远程读取策略

- 使用 `main` 而不是固定 commit/tag，目标就是始终获得最新规则。
- 每个新会话重新读取清单和所需规则，不把上一会话缓存当作最新版本。
- 优先使用 Agent 自带的 Web/HTTP/GitHub 能力；没有专用能力时，可在网络权限允许的环境使用 `curl -L` 等只读方式获取。
- 不执行远端仓库提供的任意脚本来“加载规则”；远程规则只作为文本指令读取。
- 如果运行环境不允许联网，明确说明远程规则未加载，并继续遵循本地项目事实；不要静默使用猜测版本。

## 平台适配

不同 Agent 对远程 instruction/include 的原生支持不同，不要假设 `AGENTS.md` 中写一个链接就会自动 include。

优先方案始终是：本地 `AGENTS.md` 明确要求在新会话开始时读取中央清单与规则。

如果某个平台已经提供可靠的原生远程 instructions 配置，可以额外生成平台配置，但不要让整个初始化方案依赖单个平台特性。

## 已有项目升级

已有项目使用本 Skill 时：

- 不直接覆盖现有 `AGENTS.md`；
- 先保留项目特有内容，再把通用重复规则替换为中央引用；
- 发现现有规则与中央规则冲突时，优先判断它是不是项目事实。项目事实保留；只是旧版通用偏好则迁移到中央最新版；
- 如果存在目录级 `AGENTS.md`，只有当该目录确实需要不同规则时才保留，不为层级本身创建规则文件。

## 输出要求

完成初始化后明确给出：

- 识别出的项目 profile；
- 新建或修改的 `AGENTS.md`；
- 保留的项目特有规则；
- 本地 bootstrap 使用的中央清单 URL；
- 本次实际加载的中央规则；
- URL 连通性检查结果；
- 如果做了 Git 修改，给出分支和 commit/PR 状态。
