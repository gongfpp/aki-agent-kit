# aki-open-source-audit

## 目标

回答一个明确问题：**这个仓库现在是否适合公开？**

默认只审计，不自动删除、重写历史或旋转凭据；用户明确要求整改时再执行修改。

## 审计范围

同时检查当前工作树和能够访问的 Git 历史，重点覆盖：

- API Key、Token、密码、证书、私钥、Cookie、连接串、`.env` 与本地凭据；
- 内网域名/IP、内部服务地址、账号、员工/客户/测试用户数据和其他不应公开的信息；
- 日志、dump、截图、导出文件、数据库样本、缓存、构建产物和本地路径；
- Git 历史中已经删除但仍可恢复的敏感内容；
- License、NOTICE、第三方依赖许可证和再分发约束；
- 图片、音频、字体、模型、游戏素材、数据集等第三方资产的公开授权边界；
- README、示例配置、Issue 模板和文档中可能泄露的信息；
- 大文件、无关二进制、临时文件和不应进入公开仓库的开发残留。

## 判断原则

- “当前文件已经删掉”不代表历史中不存在。
- “看起来像测试数据”不代表可以公开；无法确认来源时按风险项处理。
- 许可证和素材授权只依据仓库中能验证的声明与来源，不凭经验猜测。
- 对疑似凭据先报告位置与类型，输出时避免完整复述秘密值。
- 如果真实秘密曾进入 Git 历史，优先建议立即轮换；历史重写属于破坏性操作，只有用户明确确认后才执行。

## 工作流

1. 确认仓库公开目标、默认分支和当前 Git 状态。
2. 扫描高风险文件类型、配置、文档和常见敏感模式。
3. 检查 `.gitignore`、跟踪文件与生成/本地文件边界。
4. 检查 Git 历史中的高风险路径和已删除敏感候选。
5. 核对许可证、依赖和第三方资产来源。
6. 对每个候选读取上下文，排除明显误报。
7. 给出是否可以公开的明确结论和阻断项。

## 输出

按以下级别输出：

- **阻断**：公开前必须解决，例如真实凭据、个人/内部数据、明确无权分发的资产；
- **公开前修复**：应在公开前清理或补齐，例如许可证缺失、内部地址、无关 dump；
- **需复核**：证据不足，需要人工确认授权或数据来源；
- **已确认无阻断**：已检查且没有发现阻断证据的重点区域。

每个问题包含位置、证据、风险和最小整改建议。

## 整改模式

用户要求修复时：

- 当前树问题优先做最小安全清理；
- 涉及历史秘密时先轮换秘密，再讨论历史清理；
- 不擅自执行 `reset --hard`、`push --force`、历史重写或仓库可见性变更；
- 在 Git 仓库中遵循项目 `AGENTS.md` 和中央 Git 原则完成版本管理收尾；本 Skill 不重新定义是否 push、创建 PR、合并或其他远端流程。

## 与 Superpowers 协作

本 Skill 独立可用。Superpowers 的代码审阅、调试和完成验证 可以用于整改阶段，但不能替代公开前的敏感信息、历史和授权审计。
