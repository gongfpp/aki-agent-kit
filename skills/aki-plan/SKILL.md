# aki-plan

## 目标与范围

把当前目标变成可以照着做的计划。目标模糊时先讨论，已经明确时直接拆任务；用户只想讨论某个选择时，停在讨论结果，不强行生成任务清单。

从当前对话或用户明确指定的材料确定目标、已确认选择和本次范围，再读取相关项目文件核对起点。同一项目中的其他对话、最新提交或待办不自动属于本次计划。材料不完整时说明缺失，不替用户补造需求。

适用于软件、游戏、学习、研究和内容制作等多步骤任务。简单工作直接给可执行的下一步，不为套流程扩大任务。

## 按需澄清

- 能从代码、配置、文档或实际结果查明的事实，由 Agent 自己核对。只把真正影响目标、范围或验收的取舍交给用户。
- 先问决定方向的问题，再根据答案追问后续选择；同轮问题应能独立回答。已确认的内容直接沿用，不重新进行一轮完整访谈。
- 问题用具体体验和后果表达。需要多题时编号；有明确选项时说明关键差别，给出推荐及理由，但不把推荐当成用户决定。
- 需要原型、试玩或数据才能回答的问题，提出最小验证任务，说明要验证什么、结果会影响哪项后续选择；不靠继续追问让用户猜答案。
- 用户缩小范围、结束讨论或已经明确委托 Agent 决定某类事项时，按现有授权继续。尚未确认的重大选择要标明，不写成已确定需求。

## 任务拆解

先确认希望交付的结果、已有条件和完成标准，再安排工作：

1. 大目标先分成可以检查成果的阶段，优先安排能验证主要方向的最小完整结果；只把近期准备做的阶段展开到执行细节。
2. 按成果划分任务，而不是把源码、数据、界面或文档机械分成互不连通的工作。每项应能独立展示或验证，所需的准备、内容和检查并入它服务的成果。
3. 每项说明做成什么、开始前需要什么、怎样确认完成。依赖只保留真正阻止开工的前置任务；可独立推进的工作可以并行，不强制使用多个 Agent。
4. 拆解粒度取决于工作复杂度和验证方式：足够具体到接手者知道从哪里开始，不细拆成没有独立成果的操作碎片，也不把远期未知方案提前写死。
5. 软件任务按需要注明已核实的模块、文件、接口和验证入口；游戏任务同时考虑能否实际游玩及所需素材、文案、数值和关卡。非代码任务使用适合其成果的步骤与检查方式。
6. 必须跨多处统一修改、不能独立交付的工作，按真实依赖安排兼容过渡、迁移和联合验证，不为让任务看起来独立而给出不可执行的拆法。
7. 核对计划是否覆盖本次目标，有无遗漏、重复、循环依赖或无法验证的完成标准。明确现在能开始的第一项，以及仍需用户决定或先验证的部分。

验证投入遵循项目已有原则，不额外规定统一测试方式、任务时长或提交频率。时间和成本只有在有依据或用户需要时才估算，并说明不确定性。

## 交付与执行边界

用日常用语先说明最终要做成什么，再给阶段、任务顺序、完成标准和建议第一步。列表、表格或段落按任务选择，没有内容的栏目省略。详细实现信息只保留接手者需要知道的部分，不把计划写成整份程序。

需要确认的选择集中列出。用户已经认可目标和拆解方式时，不因为生成计划又重复询问相同问题；仅有草案时明确标为待确认。

调用本 Skill 不自动开始实现、发布、合并或创建远端任务。用户同时明确要求实施时，按已有授权和项目流程衔接执行；只要求讨论或规划时，交付结果后结束。计划中的建议和勾选项不构成额外执行授权。

## 保存与更新计划

用户要求保存计划，或当前项目流程已约定保存时：

- 优先更新项目已有且属于本任务的计划文档或任务工具；需要新文档时使用项目认可的位置，只建立承载本次计划所需的最小文件。单纯请求拆解时可直接在对话中交付。
- 写入前读取原内容，确认主题和归属。只修改本任务范围，保留其他任务及已确认进度；不根据项目名或最近修改时间选中另一段对话的计划。
- 计划表达准备做什么，不把待办写成已实现功能。新增需求只更新受影响部分；已完成任务及其有效证据不因重新规划而重置，确有变化时再标明需要重做或复验的范围。
- 已存在的等价任务直接复用，必要时更新原位置。输入、项目状态和已确认决定不变时，再次保存应保持内容不变，不新增副本、时间戳或运行日志。
- 计划与其他项目材料冲突且无法确认时，保留原内容并指出差异；涉及项目文件写入时遵循项目指令与 Git 原则。

计划文件由本 Skill 负责，包括任务、依赖和完成标准。保存计划不以“长期有效、难以重建”为门槛，也不把整份任务清单交给 `aki-context-sync`。

需要把讨论中的长期项目约定写入正式文档时，再在用户要求或既有授权范围内使用 `aki-context-sync`；是否保存计划与是否同步长期约定分别判断。本 Skill 可单独使用。

## 验收

- 目标、选择和任务范围来自当前对话或指定材料，已确认的答案得到复用。
- 每项工作有明确成果和检查方法，先后关系可执行，第一步清楚；未解决的选择没有伪装成已确认决定。
- 计划没有自行扩大到其他会话，也没有把拆解、保存或讨论当成实施授权。
- 保存时只更新所属计划，保留无关内容与有效进度；相同输入和状态再次保存无差异。
- 用户看得懂要做什么、还需决定什么；已保存时提供实际文件或任务入口，未保存时不声称已经落盘。
